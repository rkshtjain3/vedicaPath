# Evidence Retrieval Policy — Vedica Query Engine

## Overview
This document specifies the evidence retrieval policies governing `@vedica/query-engine`.

---

## 1. Zero-LLM Principle
All query answers must be assembled exclusively from calculated factual outputs generated by Vedica's 11 underlying engines. No probabilistic text generation or LLM API calls are permitted at any stage.

---

## 2. Intent-Based Scope Resolution
When a user query is executed, the `QueryIntentClassifier` identifies target entities:
- **Domain Queries**: Retrieve Life Domain synthesis, D1 placements, D9/D10 divisional placements, Dasha periods, and Transit overlays relevant to that domain.
- **Planet Queries**: Retrieve Natal placement, Dignity, Planetary Strength, Shadbala Rupas, BAV points, active Dasha participation, and Gochar transits for that specific planet.
- **Timing Queries**: Retrieve Vimshottari Dasha hierarchy, active timing windows, and current transit overlays.
- **Yoga Queries**: Retrieve detected classical yogas and involved planetary placements.
- **Numerology Queries**: Retrieve birth-date-derived numbers (Life Path, Birthday, Personal Year) and name-derived numbers (Expression, Soul Urge) if full name is provided.

---

## 3. Preserving Contradictions (No Arbitrary Score Subtraction)
If a query yields both supportive (e.g., Exalted Saturn in 10th house) and challenging (e.g., Debilitated Jupiter aspect) evidence:
- Both factors are retained in their respective arrays (`supportiveEvidence`, `challengingEvidence`).
- A `MixedSignalResult` flag is raised (`detected: true`).
- The summary explicitly notes the presence of conflicting signals without masking or subtracting points.

---

## 4. Non-Predictive Disclaimer Requirement
If a query attempts to elicit a future prediction or absolute outcome (e.g., *"Will I win the lottery?"*), the query engine MUST:
- Mark `isPredictiveAttempt = true`.
- Supply a standardized non-predictive disclaimer.
- Present available chart evidence in a structured, non-predictive format.

---

## 5. Traceability & WHY Chain Requirement
Every `QueryEvidenceItem` returned MUST contain a non-empty `whyEvidence` array containing the calculation path (engine ID, rule ID, input parameter values, and threshold checks).
